# Local AI Web Bridge

A lightweight, zero-dependency, event-driven bridge for Firefox MV3 that allows any local AI agent (Antigravity, Ollama, Llama.cpp, LangChain, or custom CLI scripts) to communicate seamlessly with web-based AI platforms (**Google Gemini**, **ChatGPT**, **Claude**, **Meta AI**).

---

## 🤖 Instructions for AI Agents & Assistant Context

If you are an AI assistant or automated coding agent tasked with querying web AI models or browsing via this bridge, **you do not need to read the source files**. Use the simple interfaces documented below.

### Primary Command Line Interface (CLI)

To query the active web AI model (e.g. Google Gemini) and receive a response synchronously:

```bash
python3 /home/dusk/.config/firefox_extentions/ai_bridge/bridge.py "YOUR PROMPT HERE"
```

- **Output**: Writes streamed text directly to `stdout`.
- **Exit Code**: Returns `0` on success as soon as the response finishes generating.
- **Completion Detection**: Automatically detects when generation has stopped. You **do not need artificial sleeps** during a query call.

---

### Python Code Integration (For AI Agents & Scripts)

#### 1. Full Response (Synchronous)
```python
import subprocess

def ask_web_ai(prompt: str) -> str:
    """Send a prompt to the Web AI bridge and return the complete answer."""
    result = subprocess.run(
        ["python3", "/home/dusk/.config/firefox_extentions/ai_bridge/bridge.py", prompt],
        capture_output=True,
        text=True
    )
    if result.returncode == 0:
        return result.stdout.strip()
    else:
        raise RuntimeError(f"Web AI Bridge Error: {result.stderr}")

answer = ask_web_ai("Explain quantum computing in 2 sentences.")
print(answer)
```

#### 2. Real-Time Token Streaming (Generator)
The bridge **natively streams tokens in real-time** via `MutationObserver` as the web AI generates them. You can process tokens live as they arrive:

```python
import subprocess

def stream_web_ai(prompt: str):
    """Stream response tokens live in real-time as they are generated by the web AI."""
    cmd = ["python3", "/home/dusk/.config/firefox_extentions/ai_bridge/bridge.py", prompt]
    proc = subprocess.Popen(cmd, stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)
    
    for chunk in proc.stdout:
        yield chunk  # Emits text live token-by-token!

# Example real-time streaming usage:
for token in stream_web_ai("Write a 1-paragraph explanation of AI."):
    print(token, end="", flush=True)
```

### Multi-Turn Follow-Up Conversations

To send a sequence of follow-up prompts to the same active chat:

1. **Run prompts sequentially**: Always wait for the previous `bridge.py` process to finish before sending the next prompt.
2. **Buffer Pause**: Add a short `1.5 - 2.0s` sleep (`time.sleep(1.5)`) between follow-up prompts to allow Gemini's single-page DOM to settle.

#### Multi-Turn Python Example:

```python
import subprocess, time

def run_conversation(prompts):
    for i, prompt in enumerate(prompts, start=1):
        print(f"\n--- Turn {i}: {prompt} ---")
        cmd = ["python3", "/home/dusk/.config/firefox_extentions/ai_bridge/bridge.py", prompt]
        res = subprocess.run(cmd, text=True)
        if res.returncode != 0:
            print(f"Turn {i} failed!")
            break
        # Brief pause between follow-up turns for DOM settling
        time.sleep(1.5)

run_conversation([
    "Hi, give me a 1-sentence greeting.",
    "Now summarize key features of Python in 4 bullet points.",
    "Now summarize that takeaway in 5 words."
])
```

## 🛠️ System Features & Workspace Behavior

- **Automatic Hyprland Workspace Switching**: The bridge automatically queries Hyprland's client list, detects the exact workspace where Firefox is open, switches to that workspace using `/home/dusk/user_scripts/hypr/multi_monitor_workspace.sh`, and focuses the Firefox window before typing.
- **Hardware Keyboard Fallback (`wtype`)**: Prompts are submitted using native OS keyboard events (`Ctrl+Enter` & `Return`) after focusing the Firefox window.
- **Shadow DOM Traversal & Streaming**: `content_main.js` handles rich-textarea elements and streams tokens via `MutationObserver` back through WebSocket in real-time.

## 🔍 Diagnostics & Troubleshooting Commands

If a query times out or returns an error, use these quick commands to check and fix the system status:

1. **Check Daemon Status**:
   ```bash
   systemctl --user status localai_bridge.service
   ```
2. **Restart Daemon**:
   ```bash
   systemctl --user restart localai_bridge.service
   ```
3. **Verify Open AI Tabs**:
   Ensure Firefox has `https://gemini.google.com/app` open and active.
4. **Test Connection directly**:
   ```bash
   python3 /home/dusk/.config/firefox_extentions/ai_bridge/bridge.py "Test connection"
   ```

## 📂 File Reference Map

- **`bridge.py`**: Python CLI client & WebSocket server daemon (`127.0.0.1:8765`). Handles Hyprland workspace focus and OS keystroke submission (`wtype`).
- **`background.js`**: Extension MV3 background page. Auto-connects to WebSocket daemon and routes messages to content scripts.
- **`content_isolated.js`**: Content script running in isolated world realm.
- **`content_main.js`**: Page-level content script running in main DOM realm. Performs input typing, DOM observer setup, and streaming.
- **`manifest.json`**: Firefox Manifest V3 setup.
